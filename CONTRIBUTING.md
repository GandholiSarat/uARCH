# Contributing

Thank you for helping improve uARCH. This is an educational repository, so clarity and reproducibility matter as much as code correctness.

## Guidelines

- Open an issue before substantial changes to lab flow or public APIs.
- Keep examples deterministic, small, portable, and easy to explain.
- Document OS, compiler, DynamoRIO, and workload assumptions.
- Keep lab instructions separate from instructor reference solutions.
- Do not commit binaries, traces, build directories, editor files, or credentials.
- Use shellcheck where available and validate Markdown links and scripts locally.

## Pull Requests

Describe the learner-facing outcome, list validation commands, and call out platform-specific behavior. A pull request should leave a fresh clone understandable and runnable up to the scope it implements.
