# Contributing

Thank you for helping improve uARCH. This is a hands-on architecture repository, so clarity and reproducibility matter as much as code correctness.

## Guidelines

- Open an issue before substantial changes to the investigation flow or public APIs.
- Keep examples deterministic, small, portable, and easy to explain.
- Document OS, compiler, DynamoRIO, and workload assumptions.
- Keep participant-facing guidance separate from facilitator reference solutions.
- Do not commit binaries, traces, build directories, editor files, or credentials.
- Use shellcheck where available and validate Markdown links and scripts locally.

## Pull Requests

Describe the participant-facing outcome, list validation commands, and call out platform-specific behaviour. A pull request should leave a fresh clone understandable and runnable up to the scope it implements.
